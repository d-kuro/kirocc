# Release v0.13.0

## New Features

### Web Search (#138, #150)

Claude Code's `WebSearch` is a server-side tool (`web_search_20250305`): the client expects whoever answers `/v1/messages` to run the search. Kiro has no web search, so kirocc used to forward the definition as an ordinary tool, and every search reported zero results with no error, after billing the request.

kirocc now runs the search itself against Brave, Tavily, Exa, or a custom endpoint. It feeds the results, snippets included, back to the model, and returns `server_tool_use` + `web_search_tool_result` blocks like the Anthropic API. `max_uses`, `allowed_domains`, and `blocked_domains` are honored, and failures come back as `web_search_tool_result_error` instead of failing the request.

```bash
kirocc -web-search-provider tavily -web-search-api-key "$TAVILY_API_KEY"
```

Configure it with `-web-search-provider` (`brave` / `tavily` / `exa` / `custom`), `-web-search-api-key`, `-web-search-url` (for `custom`), and `-web-search-max-results` (default `5`), or the matching `KIROCC_WEB_SEARCH_*` environment variables. Queries leave the machine for a third-party API, so the feature is off unless a provider is named. See [Web Search](https://github.com/d-kuro/kirocc#web-search) in the README.

### Claude Opus 5.5 (#147)

`claude-opus-5-5` and `claude-opus-5-5[1m]` are now built-in mappings to the `claude-opus-5.5` Kiro SKU, and the Claude Code model picker lists "Opus 5.5 (1M context)". Opus 5.5 is an always-1M model; the `[1m]` suffix only advertises the 1M window and does not enable thinking. Effort supports the full `low` / `medium` / `high` / `xhigh` / `max` enum. Before this, sessions without catalog discovery (e.g. API-key auth) passed the ID through with a 200k window and dropped the effort.

## Bug Fixes

### Log Lines with Invalid UTF-8 (#151)

The JSON log handler (the log file, and the console in debug mode) silently dropped any line containing invalid UTF-8, whether in the message, an attribute, an error, or a nested value. The JSON encoder rejects invalid UTF-8, and `slog` discards the handler's error. Upstream error bodies cut at a byte limit could trigger this and lose exactly the line needed to diagnose the failure. Invalid bytes are now replaced with U+FFFD and the line is written.

### Trace Export with Invalid UTF-8 (#152)

With `-otel`, a single span carrying invalid UTF-8 failed the whole OTLP export batch, and every span in it was lost. Upstream error bodies, a client's request path or `User-Agent`, and `OTEL_RESOURCE_ATTRIBUTES` could all trigger this. Span strings and resource attributes are now cleaned before export.

## Code Improvements

- Update `modernc.org/sqlite` to v1.60.0 (#149)

## Breaking Changes

- A request carrying the `web_search_20250305` tool now returns `400` unless a web search provider is configured. It used to return `200` with no search results. Configure `-web-search-provider`, or drop the tool on the client (`claude --disallowedTools WebSearch`). (#138)
