# Release v0.6.0

## New Features

### Kiro API key authentication via KIRO_API_KEY (#88)

kirocc can now authenticate with a Kiro API key (`ksk_…`) presented directly to the API, so an interactive Kiro login on the same machine is no longer required. This enables running kirocc in CI, containers, and other headless environments.

- Set `KIRO_API_KEY` (and optionally `KIRO_API_REGION`), or use the `-kiro-api-key` / `-kiro-api-region` flags
- When a key is present, the SQLite credential database is never opened and no token refresh occurs; a revoked key surfaces as a 401 from the API
- Unset or empty key keeps the existing credential-database behavior unchanged
- A startup log line states the auth mode (`using Kiro API key auth_type=api_key`)

### SSE keep-alive heartbeat (#86)

kirocc now emits SSE keep-alive comments while Kiro is silent, so idle client timeouts no longer close valid long-running streaming requests.

- Configurable interval via the `-keepalive-interval` flag / `KIROCC_KEEPALIVE_INTERVAL` env (default 15s, `0` disables, values below 1s are rejected)
- A request-scoped stream session owns every downstream write for one streaming `/v1/messages` request; one session (and its heartbeat) spans retry attempts and tool-search rounds
- Transparent retry (empty visible `end_turn`, retryable invalid state) still works after a keep-alive has committed HTTP 200
- Pre-commit errors return JSON; post-commit errors are delivered as Anthropic-compatible SSE error events
- Downstream socket writes are bounded by a 30-second per-write deadline so a client that stops reading cannot wedge the stream session
