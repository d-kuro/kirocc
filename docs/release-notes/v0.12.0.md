# Release v0.12.0

## New Features

### Kiro Auto Model Selection (#128, #143)

kirocc now supports Kiro's `auto` model router. `GET /v1/models` advertises `claude-auto` (display name "Auto"), and `POST /v1/messages` accepts both `auto` and `claude-auto`. Auto bypasses thinking and effort resolution entirely and passes `auto` through to the Kiro backend, since the router picks the upstream model itself.

An explicit `KIROCC_MODEL_MAPPINGS` override for `auto` or `claude-auto` is honored: the mapping is resolved first, and Auto behavior applies only when the resolved upstream SKU is `auto`. Mapping the Auto aliases to a concrete model keeps that model's normal context routing and effort handling.

### Claude Fable 5.1 (#140)

`claude-fable-5-1` and `claude-fable-5-1[1m]` are now built-in mappings to the `claude-fable-5.1` Kiro SKU, so Claude Code sessions on Fable 5.1 resolve without going through the catalog probe. Fable 5.1 is an always-1M model; the `[1m]` suffix is a first-class alias that only advertises the 1M window and does not enable thinking. Effort supports the full `low` / `medium` / `high` / `xhigh` / `max` enum.

### Configurable Request Body Limit (#125)

The client request body cap was hardcoded at 4 MiB, which rejected long conversations Kiro would have served and wedged clients permanently since every retry sends the same body. The cap is now configurable via `-max-request-body` or `KIROCC_MAX_REQUEST_BODY`, defaults to 32 MiB to match the Anthropic Messages API, and `0` disables it. Oversized bodies return a diagnosable `413` naming the limit and how to raise it, instead of a generic `400`.

## Bug Fixes

### Empty Answers from Kiro Auto in Headless Claude Code (#139, #141)

Kiro's `auto` router sends its reasoning as a `redacted_thinking` block _after_ the text block. Claude Code's final-result extraction keeps only text following the last thinking block, so the trailing blob discarded the whole answer: `claude -p` printed nothing and exited 0 after billing the request.

Streaming now defers reasoning blobs and flushes them ahead of whichever block opens next, so a blob that genuinely precedes text or a tool call keeps its position. A blob still pending at the end of a round that has text but no tool call is dropped; tool rounds and reasoning-only rounds keep it for replay. Non-streaming responses always order `redacted_thinking → thinking → text → tool_use`. Text held back for a partial thinking tag or stop-sequence prefix is flushed after blob retention is decided, so the start of the answer is never lost either.

### Images in Conversation History (#134)

Sending an image worked on the first request, but every follow-up in that conversation failed with `ValidationException: Improperly formed request`. Once the image message moved into history, the image was dropped and an image-only message serialized as an entry with empty content, which Kiro rejects.

History entries now carry images the same way the current message does, images nested in history `tool_result` blocks are promoted to the message-level image channel, and a history entry without tool results never has empty content.
