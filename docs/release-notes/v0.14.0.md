# Release v0.14.0

## New Features

### Configurable Response Header Timeout (#155, #159)

kirocc waited at most 30s for Kiro's response headers, and the limit was hardcoded. Kiro sends headers only once the model starts, so a large prompt or a high effort could exceed it and trigger `http2: timeout awaiting response headers` retries.

The limit is now set with `-response-header-timeout` or `KIROCC_RESPONSE_HEADER_TIMEOUT`. It still defaults to `30s`, and `0` means no limit. Values below `1s` (other than `0`) are rejected at startup, since they would make every request time out.

```bash
kirocc -response-header-timeout 2m
```

## Bug Fixes

### Empty Replies in Long Sessions (#155, #159)

Claude Code often sends a `tool_result` turn followed directly by a second user turn (hook feedback, system reminders, a queued prompt). kirocc kept the two apart and inserted a synthetic `(empty)` assistant turn between them to satisfy Kiro's role alternation. In long sessions the model then saw many of its own past turns as `(empty)` and started replying with empty `end_turn` responses.

Consecutive user turns are now merged into one. Tool results and images keep their order, and each turn's text is joined with a newline.
